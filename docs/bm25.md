# BM25 单路检索（第 17 步）

## 入口与结果

`app.services.bm25.search(factory, user_id, kb_id, query, top_k=5, trace=None)` 返回既有 `RetrievedChunk` 列表。user_id 必须来自后端认证，脚本通过环境变量中的 JWT 验证身份；服务不把请求体的身份字段当作认证。top_k 只接受 1～20 的整数，query 限 1～4000 字符。

本步提供独立服务和评测 CLI。现有 `/search`、固定 RAG 问答及向量评测继续使用原向量策略；本步没有增加融合、重排或 BM25 HTTP 路由。

结果保留 chunk/document/build/kb ID、文档名、原正文、页码和标题；`rank` 从 1 开始。BM25 的 `distance=null`，`bm25_score` 是原始 Okapi 分数，降序排列，同分按 chunk_id 升序。向量结果的 distance 含义不变，新增 bm25_score 默认为 null。两类分数不可直接比较，均不是答案正确概率。

## 固定预处理

版本 `jieba-identifiers-v1`，文档和查询调用同一个函数：

1. 先做 Unicode NFKC 和 casefold，统一全角 ASCII 与大小写，仅用于检索。
2. 形如 `[a-z0-9]+(?:[-_.][a-z0-9]+)*` 的标识符作为完整词项：`HTTP` → `http`、`E_AUTH_401` → `e_auth_401`、`NX-210-P` → `nx-210-p`，`680.50` 保持完整。
3. 连续中日韩统一表意文字区间 U+3400～U+9FFF 交给 jieba 精确模式，`cut_all=False, HMM=False`。
4. 丢弃空白和其他标点；不增加停用词、词干、自定义词典、同义词扩展。文档/查询均保留重复词项。

`NX-210-P` 与 `NX-210-P2` 不作为同一标识符；`HTTP` 与 `http` 相同。连接符必须为规则中的 ASCII `-_.`，不自动把任意 Unicode 横线或人为断开的产品号视为同一词。当前分词规则面向模拟中文/ASCII 资料，不声称覆盖全部语言及复杂化学式等术语。

词面检索没有语义改写能力：只写“休假”的片段不因查询“请假”而自动命中。保留常见词会产生词面重叠的低相关候选，不能把“有共同词项”当作语义相关或足以回答。

采用 `BM25Okapi(k1=1.5, b=0.75, epsilon=0.25)`，没有通过 dev/test 调整参数。词频和文档长度会影响分数；小集合的 IDF 可为零或负数，epsilon floor 也不保证正分。候选条件为**查询与块至少共享一个规范化词项**，然后按实际分数排序，禁止用 `score > 0` 替代。空库、全部只含标点、无共同词项均返回空。

## 授权、更新和成本

每次请求：

1. `require_kb_member` 授权；SQL 再限定该用户的 membership、当前 kb_id、未删除文档及 ready 的 active build，读取正文和定位，不载入向量。
2. 关闭数据库会话，创建本次 jieba Tokenizer、分词集合和 BM25 对象，计算候选。
3. 返回前再次检查成员资格并读取当前集合；内容、构建或集合变化返回 `409 BM25_CORPUS_CHANGED`，撤销成员返回与未知库相同的 NotFound。

BM25 不依赖 Embedding 提供商、维度或向量，不按 Embedding 配置过滤文本；仍严格遵守 ready/active 发布边界。各库的 IDF 独立计算，不能先建立全库词频再按权限过滤结果。

**不跨请求缓存语料、分词、词频或候选。** jieba 依赖自身公开词典的磁盘缓存，它不含项目块或成员权限；每次构造 Tokenizer 都重新初始化内存词典。此实现避免私有集合缓存失效逻辑，但每次都要读库、初始化词典、分词和建索引，并在返回前多读一次集合；适合当前小规模演示，不构成性能承诺。

trace 与逐题输出记录：`load_ms`、`tokenize_ms`（包括本次词典初始化）、`index_ms`、`score_ms`（含词项交集及排序）、`revalidate_ms`、`total_ms`；另有 corpus_chunks、corpus_utf8_bytes、corpus_tokens、overlap_candidates。总耗时覆盖服务调用，不含 CLI 登录校验、评测快照和报告写盘。报告分组成本，不把建 BM25 对象的耗时单独当成请求总成本。

复杂度随本库文本与词项数增加：加载和分词需访问全部块；BM25 对每个查询词扫描文档词频，排序最坏需排序全部词面候选。没有测量并发容量、最大规模或内存峰值；实际小样本成本见下方运行记录。

## 运行与保存

在 `backend` 目录（PowerShell）：

```powershell
uv sync --locked
# 默认 dev 预检；draft 阻塞正式效果统计。
uv run --locked python -m app.evaluate_bm25

# 已按 README 登录取得 $session，并已把清单资料按 A/B 归属完整入库。
$env:EVAL_BEARER_TOKEN = $session.access_token
# 映射文件示例：{"A":"实际 A 库 UUID","B":"实际 B 库 UUID"}
uv run --locked python -m app.evaluate_bm25 --run --draft-diagnostics --mapping ../artifacts/eval-kb-map.json

# 真正完成 dev 人工复核后，去掉 draft-diagnostics 才统计正式检索指标。
uv run --locked python -m app.evaluate_bm25 --run --mapping ../artifacts/eval-kb-map.json
```

沿用 DATABASE_URL、JWT_SECRET 环境配置；BM25 无需 OPENAI_API_KEY，不调用 Embedding 或 Chat。`--questions` 指定已复核文件，`--output` 指定新的空产物目录。test 需 `--split test` 并通过原冻结检查，禁止 `--draft-diagnostics`。退出码 0 完成、1 含逐题错误、2 预检未运行/阻塞；已存在目录拒绝覆盖。

每次新建 `artifacts/eval/bm25-*`，与向量目录分开，输出：

- `results.jsonl`：逐题原始候选、BM25 分数、真实位置、gold、成本与执行状态。
- `summary.json` / `report.md`：样本量、成功/错误/未运行、成本均值，以及仅已复核样本可用的检索指标。draft 模式正式指标为 null，仍保留实际原始候选。
- `manifest.json`：配置版本、参数、库映射哈希、数据/源码/锁文件哈希、jieba/rank-bm25/numpy 版本、词典 SHA-256、机器和并发信息、完整有效语料/构建/切块快照。BM25 不用向量，快照不保存向量值；保留构建模型标识以说明来源。
- `input_questions.json`：原始题目版本。

正式指标沿用第 16 步的完整标注原文与位置匹配；无 gold 题不入检索分母。仅执行检索，拒答、回答引用和事实正确性不适用。不存在真实向量效果报告时，不进行两路质量优劣结论。所有报告保存在 Git 忽略目录，不能提交私有原文。

## 依赖依据

锁定 jieba 0.42.1、rank-bm25 0.2.2 及其 NumPy 依赖；未改变其他策略参数。jieba 官方说明精确模式、HMM 参数及独立 Tokenizer：[jieba 文档](https://github.com/fxsjy/jieba)。rank_bm25 不代做预处理，因此调用方须对查询和文档使用同一规则：[rank_bm25 文档](https://github.com/dorianbrown/rank_bm25)。零/负 IDF 与实际评分依据 [BM25Okapi 官方实现](https://github.com/dorianbrown/rank_bm25/blob/master/rank_bm25.py)。jieba 在 Python 3.12 首次导入时可显示其源码字符串转义 SyntaxWarning，测试中没有抑制；该警告不意味着接口调用失败。
