# 企业知识库问答系统需求（第 1 步）

## 1. 目标与范围

面向模拟企业资料，提供可演示的知识库文档管理、检索和带引用的问答，用于展示 RAG 开发能力。所有资料应为可公开使用的模拟内容。本文描述可验收的产品行为；本步不实现业务代码。

下表中“基础范围”是后续优先实现的能力，“后续阶段”须由单独编号任务启动，不在当前步骤提前实现。

| ID | 阶段 | 需求 | 可执行检查 |
| --- | --- | --- | --- |
| R1 | 基础范围 | 用户在每个知识库中具有管理员、普通成员或无授权三种状态；同一用户在不同知识库的角色可不同。管理员拥有成员的检索、问答和查看授权来源能力。 | 用同一账号分别加入 A 库为管理员、B 库为成员，验证 A 库可管理文档，B 库只能使用成员能力；未加入的 C 库按 S6 拒绝访问。 |
| R2 | 基础范围 | 管理员可向其管理的知识库上传文档、查看每个文档的处理状态、删除文档；普通成员不能执行这些管理操作。状态至少能区分处理中、可检索和失败，并提供失败原因。 | 按 S1、S3、S7 操作；再以普通成员身份尝试上传、查看管理状态和删除，均应被拒绝。 |
| R3 | 基础范围 | 成员和管理员可在授权知识库中检索、提问并查看引用所指的来源；无授权用户不能读取检索结果、回答或来源。 | 按 S4、S6 操作，并以管理员重复 S4。 |
| R4 | 基础范围 | 系统可维护多个知识库；一次检索或问答必须且只能明确选择一个知识库，结果不得混入其他库。 | 在 A、B 库放入不同的独有事实，仅选择 A 提问，检查答案和引用只来自 A；省略库或一次传入多个库时请求被拒绝。 |
| R5 | 基础范围 | 支持 UTF-8 Markdown、UTF-8 TXT 和可提取文字的 PDF。扫描件、纯图片 PDF、损坏文件及不支持的类型应给出明确提示，不能成为可检索资料。 | 对三种合法格式分别执行 S1；对损坏文件、不支持的类型和扫描件分别执行 S3。 |
| R6 | 基础范围 | 同一知识库中，内容字节完全相同且尚未删除的文件重复上传时，返回已有文档标识，不新增可检索副本；不同知识库各自独立。删除后重新上传按新文档处理。 | 按 S2 比较文档标识、列表数量和检索结果数；在另一库上传相同文件，确认有该库独立的文档。 |
| R7 | 基础范围 | 基于资料作答时，答案应包含可打开的引用。引用至少标识文档、定位位置和对应的来源片段；PDF 用页码，Markdown/TXT 用标题或行号。引用及来源只能在当前授权库中查看。 | 按 S4 检查答案事实与来源片段相符、定位可用；按 S6 检查无授权用户无法打开引用。 |
| R8 | 基础范围 | 当前库没有足够证据时，系统应明确拒答或要求补充信息，不编造事实或引用。 | 按 S5 使用库中不存在的事实提问，检查回复表达资料不足且不提供虚构引用。 |
| R9 | 基础范围 | 删除成功后，该文档不得再出现在新发起的检索、问答或可访问来源中；已有回答中的引用若指向已删除文档，也不能继续打开其内容。 | 按 S7 在删除成功后重新检索、提问和打开旧引用。 |
| F1 | 后续阶段 | 增加混合检索，结合关键词与语义检索；具体融合策略和参数待实验确定。 | 用同时包含精确术语和语义改写的固定测试集，分别记录两路候选及最终排序；验证结果仍仅来自所选授权库。 |
| F2 | 后续阶段 | 增加后台入库，上传请求可先返回文档标识，状态随后更新；处理失败可见原因，未完成的文档不能被检索。 | 上传测试文件后轮询状态，确认处理期间不可检索、成功后可检索；注入解析失败，确认最终状态为失败且无可检索内容。 |
| F3 | 后续阶段 | 增加只能调用预先允许的工具、且每次请求调用次数有上限的 Agent；上限和工具清单待确定。 | 用可计数的 fake 工具验证：允许的调用在上限内执行；超限和未允许的工具调用被拒绝，且不发生实际调用。 |

## 2. 验收场景

以下场景使用 A 库、B 库、A 库管理员甲、A 库普通成员乙，以及未获 A 库授权的用户丙。示例文件只含模拟资料。每个场景在实现后均应能由自动化测试或重复的手工步骤执行；当前仅定义条件，尚未运行产品验收。

### S1 上传合法资料

- **Given** 甲已获 A 库管理员权限，准备三份内容可提取的 `.md`、`.txt` 和文本型 `.pdf` 文件。
- **When** 甲分别上传文件，并查看各文档状态直至处理结束。
- **Then** 每次上传返回文档标识；最终状态为可检索；乙在 A 库检索文件中的独有文字能找到对应文档，文档状态对甲可见。

### S2 重复上传同一文件

- **Given** 甲已向 A 库上传一份可检索文件，并记录其文档标识、文档列表数量和对应检索结果。
- **When** 甲再次向 A 库上传字节完全相同的文件。
- **Then** 返回原文档标识；文档列表和可检索副本数量不增加；B 库的文档不受影响。

### S3 上传损坏或不支持的文件

- **Given** 甲拥有 A 库管理员权限，并准备损坏的 PDF、不支持的文件类型和无可提取文字的扫描 PDF。
- **When** 甲分别尝试上传这三种文件。
- **Then** 每次均能看到具体的失败或不支持原因；扫描 PDF 明确提示暂不支持扫描件；这些文件均不进入可检索状态，也不产生可检索内容。

### S4 提问并查看引用

- **Given** A 库已有可检索资料，包含一个仅在 A 库出现的明确事实；乙拥有 A 库普通成员权限。
- **When** 乙选择 A 库提问该事实，并打开答案中的引用。
- **Then** 答案基于 A 库资料，引用能定位到包含该事实的授权文档和来源片段；答案与引用中均不出现 B 库内容。

### S5 询问知识库没有的信息

- **Given** A 库资料不包含某个具体事实，乙拥有 A 库普通成员权限。
- **When** 乙选择 A 库询问该事实。
- **Then** 回复明确说明资料不足而拒答，或要求补充必要信息；不声称知道该事实，也不生成无法对应到 A 库资料的引用。

### S6 用户访问未授权知识库

- **Given** 丙未获 A 库授权，且知道 A 库及其中某文档的标识。
- **When** 丙尝试检索、问答、查看文档来源或执行文档管理操作。
- **Then** 每次请求均被拒绝，不返回 A 库的文档内容、检索片段、引用或处理状态；B 库的授权不授予 A 库访问权。

### S7 删除文档后再次检索

- **Given** A 库中只有一份文档包含某独有事实；甲已记录该文档标识，乙已取得引用该文档的回答。
- **When** 甲删除该文档且收到删除成功结果，乙重新检索、提问该事实并尝试打开旧引用。
- **Then** 新检索和回答不再使用已删除文档；旧引用不能继续读取其内容；新回答按 S5 处理资料不足。

## 3. 明确不做

- 当前步骤不编写业务代码、测试代码或架构实现。
- 基础范围不做扫描件 OCR、图片或多媒体解析；扫描件给出暂不支持提示。
- 基础范围不做一次跨多个知识库的联合问答。
- 基础范围不做混合检索、后台入库或 Agent 工具调用；这些属于 F1–F3 的后续编号任务。
- 不接入真实企业内部系统，不使用真实敏感资料，也不提供公网部署。

## 4. 项目假设

- 演示资料和用户均为可控的模拟数据；每次请求能获得可信的用户身份，具体认证方式待确定。
- 角色按知识库授予；无授权状态默认拒绝访问。管理员具备该库成员能力，但不能凭 A 库权限访问 B 库。
- “相同文件”按同一知识库内的原始文件字节判断，与文件名无关；文档删除后可重新上传。
- 上传成功仅表示系统接受该文档；是否可用于检索，以文档状态变为“可检索”为准。
- 删除成功是对外可见的边界：此后新请求不能读取该文档，即使底层清理仍在继续。
- 问答质量需要在单独的真实模型实验中评估；可控 fake 模型测试只验证流程和边界行为。

## 5. 仍需确定的配置

以下配置在实现对应功能前确定并记录，不在本步虚构数值或供应商：

| 配置 | 待确定内容 |
| --- | --- |
| 部署与认证 | 本地演示或其他运行环境；身份来源、登录方式和授权管理入口。 |
| 文件约束 | 单文件大小、单库容量、页数上限、文本编码错误处理、加密 PDF 的提示。 |
| 文档处理 | 分块规则、索引实现、失败后重试方式、删除后的底层清理策略。 |
| 检索与回答 | 候选数量、排序参数、模型供应商、资料不足判定方式、引用展示格式。 |
| 后续能力 | 混合检索融合策略、后台任务运行方式、Agent 工具白名单与调用次数上限。 |

## 6. 性能与效果的测量方法

不预设并发量、准确率或延迟达标值。实现后固定测试语料、问题集、硬件环境、模型版本和运行配置，分别记录：

- 上传至可检索的耗时、解析失败数及文档规模；区分冷启动和重复运行。
- 检索耗时与完整问答耗时的分布（如中位数和 95 分位数），并记录每次测量的请求数和并发设置。
- 固定问答集上的答案有据率、引用定位正确率和无答案问题的拒答表现；保存逐题证据与人工判定标准。
- fake 模型测试与真实模型实验分别报告，不能把前者解释为真实 RAG 效果。
